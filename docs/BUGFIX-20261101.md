# Bug 清扫与体验修复（2026-11-01）

## 0. 结论先行

- 生产域名 `https://picacg.example.com/` 做了两轮 E2E（1440×900 / 390×844），
  覆盖探索 8 个源页签、搜索、详情、阅读器、下载、我页、onboarding、收藏。
- **搜索页“卡死”在现有生产版本上无法复现**：PreSearchPage 没有任何网络 await，
  标签数据来自打包资源；断网后打开仍为 0.5s。本次补上了“源列表为空/初始化失败”的
  降级页，避免旧版本在源列表异常时因 `ComicSource.find(target)!` / `sources.first`
  直接抛异常而表现为空白/卡死。
- 实际发现并修复 7 处问题，其中 3 处影响主流程：
  1) hitomi 探索首屏 15–30s（一个 galleryblock 失败整页失败）；
  2) onboarding“完成”无防重，重复点击会并发 `ComicSource.reload()`；
  3) picacg 未登录探索只有“重试”，没有登录入口。
- 最终 `flutter build web --release --no-web-resources-cdn` 通过，产物在
  `app/build/web`，**未部署**。

## 3. 真实问题（按严重度）

### P1-1 hitomi 探索首屏极慢，且单条失败导致整页失败

- **现象**：切到 hitomi 页签后转圈 15–30s；生产实测 18s 仍只有 spinner。
- **根因**：`HitomiHomePageLogic.get()` 先取 100 个 gallery id，再在
  `parseIds()` 中串行分批拉取 100 个 `galleryblock` 简介，**全部完成前不结束 loading**；
  任意一个 `getComicInfoBrief` 失败会 `message=...; return false`，整页变成错误页。
- **修复**：`lib/pages/hitomi/hitomi_home_page.dart`
  - 每批 5 个完成后立即 `update()`；首批成功即 `loading=false`，卡片先出现；
  - 单条失败只记录 warning 并跳过，不再拖垮整页；
  - 增加 `_fetching` / `_loadingNext` 防重入（build() 内触发 get/loadNextPage 的旧模式）；
  - `refresh_()` 清空 `hitomiComics` 与请求标记，避免重试重复。
- **验证**：生产旧构建 18s 仍 spinner（`02-hitomi-old-stuck-loading.png`）；
  新构建首批卡片 2.7s（`03-hitomi-new-first-cards.png`）。

### P1-2 onboarding“完成”可重复点击，可能并发 reload 源

- **现象**：最后一步“完成”按钮无 loading/disabled，快速双击会并发执行
  `ComicSource.reload()`（清空并重建 `ComicSource.sources`）。这会让源列表短暂为空/
  半初始化，随后打开搜索页可能因找不到源而空白或异常。
- **修复**：`lib/pages/welcome_page.dart`
  - `_WelcomePageState.finish()` 加 `finishing` 锁；
  - 按钮 `isLoading` + `disabled`，重复点击不会再次执行；
  - `reload()` 包 try/catch，失败也仍进入主界面并记录日志。
- **验证**：全新 context 双击“All Done”，0.7s 进入主界面
  （`07-onboarding-finished.png`），无重复 MainPage/白屏。

### P1-3 搜索页：历史“卡死”不可复现；补齐无源降级

- **现象**：历史问题描述为打开搜索页长时间转圈。
- **定位结果**：
  - `PreSearchPage` / `PreSearchController` **没有任何 await 网络请求**；
  - 标签建议来自 `rootBundle` 的 `assets/tags.json`（1.3MB，首次解码在主 isolate，
    但不阻塞页面构建）；
  - 生产打开 0.4s，局域网新构建 0.5–0.8s，**断网后 0.5s**。
  - 旧代码真正会崩的路径：所有源被禁用/初始化失败时
    `searchSource.first`、`ComicSource.find(target)!`、`searchPageData!` 会抛异常，
    表现为页面空白（用户感知为卡住）。
- **修复**：`lib/pages/pre_search_page.dart`
  - `searchPageData` 改为可空，所有使用点判空；
  - 构造函数只把有 `searchPageData` 的源作为候选，空列表直接降级；
  - `build()` 在目标源不可用时渲染“没有可用的漫画源 …”提示页；
  - `search()` 对无效目标 toast 提示，不再解引用 null；
  - `findSuggestions()` 对 `enableTagsSuggestions` 判空。
- **验证**：把 `settings[82]` 置为 `000000` 关闭全部源后，新构建显示降级页
  （`11-search-no-source-fallback.png`），不再空白/异常。

### P1-4 picacg 未登录探索没有登录入口

- **现象**：“未登录 + Retry”，重试永远不会成功。
- **修复**：
  - `lib/components/loading.dart` 的 `NetworkError` 新增 `extraAction`；
  - `lib/pages/explore_page.dart` 在错误信息包含“未登录”时提供“去登录”按钮，
    打开 `AccountsPage`。
- **验证**：屏蔽 `/api/store/account` 并移除本地 picacg 凭据后，探索页出现
  “Retry / 去登录”（`06-picacg-unauth-login-cta.png`）；点击后打开账号页
  （`10-login-cta-opens-accounts.png`）。

### P2-1 图片收藏/历史页空数据时是纯白页

- **现象**：图片收藏 0 条时只有标题，无任何提示；HistoryPage 空数据同样空白。
- **修复**：
  - `lib/pages/image_favorites.dart`：空状态图标 + “暂无图片收藏 / 阅读时收藏的图片会显示在这里”；
  - `lib/pages/history_page.dart`：空状态“暂无阅读历史”，搜索无结果时“没有匹配的历史记录”。
- **验证**：`04-image-favorites-empty.png`、`05-history-empty.png`。

### P2-2 我页计数在子页面返回后可能不刷新（controller tag 不匹配）

- **现象**：从“图片收藏”删图后返回我页，计数仍是旧值；`LocalFavoritesManager`
  的“me page” tag 也从未注册过。
- **修复**：
  - `lib/pages/me_page.dart` 用 `StateBuilder<SimpleController>(tag: "me_page")` 包裹；
  - `lib/foundation/local_favorites.dart` 的 updateUI tag 改为 `me_page`；
  - `lib/pages/favorites/local_favorites.dart` 导入收藏夹后的 `StateController.find`
    改为 `findOrNull`（原写法在没有 controller 时会抛 StateError）；
  - `lib/foundation/image_favorites.dart` 删除图片收藏后补一次 `me_page` 通知。
- **验证**：`flutter analyze` 干净；Me 页 History 计数在阅读后 6→7 实测更新，
  删除路径未做破坏性手工回归（避免改动共享历史数据）。

### P2-3 `LoadingState` 异步回调可能 setState after dispose

- **现象**：hitomi 搜索等页面在加载中快速返回，`loadData().then` 仍会 setState。
- **修复**：`lib/components/loading.dart` 的 `initState` / `retry` 回调加
  `if (!mounted) return;`。
- **验证**：`flutter analyze lib/components/loading.dart` 无问题；hitomi 搜索/详情路径回归正常。

### P2-4 重登录递归调用未 await，异常会逃出 try/catch

- **位置**：`picacg methods.dart`（get/post 递归）、`nhentai_main_network.dart`（302 跟随）、
  `jm_network.dart`（reLogin 后重试）。
- **问题**：`return get(...)` 在 async try 内不等待，递归 future 抛错时外层 catch 捕获不到，
  会变成未处理异常（UI 只看到失败/无提示）。
- **修复**：改为 `return await ...`，让异常进入既有 `Res.error` 分支。
- **验证**：`flutter analyze` 对应 warning（unawaited_return_in_try_block）消失；
  JM/nhentai 搜索与阅读回归正常。

## 4. 噪音鉴别（不是前端 bug）

| 控制台/网络现象 | 判定 | 说明 |
|---|---|---|
| `403 POST /api/tunnel` → `tencent.jmdanjonproxy.xyz/media/...jpg`，body `host_not_allowed` | **真实，但不属于前端/本任务范围** | 网关出站白名单没包含 JM 新图片域名；需 gateway allowHosts 调整 |
| `403 GET /api/img/<token>` | **真实，但属 image_manager/网关范围** | 解 token 得 `exp`，历史/收藏里存的是已过期签名 URL（本次实测过期约 2 分钟）。需 image_manager 重新签名或网关放宽 |
| `500 / 520 / 522 POST /api/tunnel` | 噪音（上游源站） | JM CDN 返回登录 HTML/522、picacg 400 invalid email、hitomi 522；UI 已有错误/重试 |
| `Refused to set unsafe header "user-agent"` | 噪音 | 浏览器禁止直接设置 UA；真实请求头走 `X-Pica-Req-Headers`，不影响功能 |
| `Could not find a set of Noto fonts ...` | 噪音/字体兜底 | 个别 CJK 字形缺字，仅影响字形覆盖 |
| 控制台 `Failed to load resource: 403/500/520` | 多数为上面上游/图片代理 | 需结合 `X-Target-URL` 与响应体区分，不能直接判为前端异常 |

## 6. 遗留问题 / 建议

1. **网关 allowHosts**：`tencent.jmdanjonproxy.xyz` 未放行，JM 新封面 403。需在
   `gateway` 配置/代码侧补白名单（本任务禁止改动 gateway）。
2. **签名图片 URL 过期**：历史/收藏封面保存了带 `exp` 的 `/api/img/<token>`，
   过期后 403。建议 image_manager 在读取本地保存的 `/api/img/` URL 时重新签名，
   或网关对历史封面使用长期 token（image_manager 由另一 agent 独占，未改）。
3. **上游 500/520/522**：JM/hitomi/picacg 偶发；目前详情页会显示原始错误文案
   （如 “Invalid Status Code: 500 ...”），后续可统一成更友好的中文提示。
4. **Hitomi 后续批次仍可能慢**：首屏已从 15–30s 降到 2.7s；100 条简介仍在后台串行
   分批拉取，弱网下滚动到底部仍可能等待。
5. **Me 页计数 controller**：已接入 `me_page`，但“从收藏夹导入”等极少数路径仍依赖
   `findOrNull`，没有 controller 时静默跳过（可接受）。
